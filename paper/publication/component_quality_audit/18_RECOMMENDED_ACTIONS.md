# Recommended Actions — Ranked Plan

**Derived from:** `15_ISSUE_REGISTER.csv` (**154 rows**: 146 report issues + 8 dated amendment records)
via `18_ACTION_PLAN.csv` (**154 rows**, `rank` 1–154) and
`diagnostics/results/cqa_actions.json`, both generated by `diagnostics/cqa_actions.py`.
**Evidence base:** the issue register itself plus the 15 component reports (01–14, 17) whose
evidence fields each row inherits. No number below is new; every count is recomputed from the CSV
files at write time and printed in §2.
**Independence:** this report adds **no measurement**. It ranks, groups and sequences findings that
components A–P already established, and it re-reads `paper/publication/final_validation/
REMAINING_PUBLICATION_BLOCKERS.csv` (B1–B21) to say which findings the project's own blocker list
has already noticed and which are new to it.

> **Scope.** This is a plan, not an execution. **No item in this document has been performed**, with
> the single exception of the nine `A_APPLIED` rows, which record corrections this audit already made
> to its own reports (§2.5). Nothing here touches a frozen release, changes a catalogue/terminology/
> mapping/triple/CDM record, re-runs extraction, or re-derives a metric. Where an action *would* change
> a frozen artefact, the row is classed `BLD` and is explicitly out of scope today.

## 1. How the plan was built

### 1.1 Six action classes

Each of the 154 register rows was assigned exactly one class. The assignment is explicit in
`diagnostics/cqa_actions.py` (`PLAN`: an `id → (class, human_required)` table), not inferred from
keywords, so the classification is auditable and rerunnable. `cqa_actions.py` fails loudly if any
register row is missing from the table or unclassified — which is why the totals reconcile exactly.

| Class | n | Meaning | Doable without touching a frozen record? |
|---|---|---|---|
| `DOC` | 83 | A text/statement change: a limitation sentence, a corrected figure in the manuscript or in release-adjacent documentation, a renamed metric in the *next* release, an explicit disclosure. | **yes** |
| `ART` | 44 | An added artefact that does not alter a frozen value: a DDL file, a crosswalk table, a verb vocabulary, a manifest, a prompt bundle, an exclusion-flag column shipped alongside. | **yes** |
| `BLD` | 13 | Requires a rebuild or a rerun. The frozen artefact changes, or the information no longer exists and must be regenerated. | **no** |
| `HUM` | 3 | Requires a human decision that computation cannot make: legal review, adjudication. | yes to *perform*, but not by an algorithm |
| `A_APPLIED` | 9 | Already done by this audit as a dated, additive correction. Listed for completeness and to keep the register closed. | n/a |
| `NONE` | 2 | No action recommended; recorded so the finding is not silently dropped. | n/a |

The `doable_without_touching_frozen_records` flag is not a second opinion on the class: it is
`no` for exactly the 13 `BLD` rows and `yes` for the other 141. **141 / 154 = 91.6%** of the register
can be addressed without rebuilding anything, which is the single most useful fact in this plan.

`human_required = yes` for **6** rows, and only 3 of those are class `HUM`. The other three are
findings whose *fix* is documentary but whose *evidence* must come from a person before it can be
stated as fact:

| id | class | why a human |
|---|---|---|
| `CQA-N-01` | HUM | 179 withheld papers need a legal/library determination (135 licence unknown, 29 NC-ND, 12 NC, 3 NC-SA — three different problems, not one queue). |
| `CQA-K-02` | HUM | The BugSigDB comparison's adjudication slot is empty in all nine fields; a 10% sample (≈150 items) must be adjudicated. |
| `CQA-K-03` | HUM | `body_site` concordance is 24.6%; the 57 mismatching items must be read to decide whether the defect is ours or the matching rule's. |
| `CQA-J-01` | ART | 60.7% "not well formed" is a model verdict with an unshipped rubric; 50 drops need a human spot-check before the figure is quoted as fact. |
| `CQA-I-02` | DOC | No benchmark covers the CDM's types. Disclosure is enough for this cycle; a 200-span hand annotation would be the real fix but is an option, not a requirement. |
| `CQA-N-10` | DOC | The deposit's 7 TODO placeholders centre on which of three licensing regimes applies to which part of the bundle — a decision, not an edit. |

### 1.2 Ranking rule

`severity band (CRITICAL > HIGH > MODERATE > LOW) → action_class (HUM > BLD > ART > DOC > NONE >
A_APPLIED) → component letter → register order`.

Severity dominates because a documentation fix to a critical defect still leaves the defect critical
until the sentence exists. Class is second because it is the only ordering that encodes *who can do
it*: `HUM` and `BLD` items gate everything downstream of them, while `DOC` items are numerous but
individually cheap. Ranks are contiguous within bands — CRITICAL 1–12, HIGH 13–55, MODERATE 56–124,
LOW 125–154 — so the CSV can be sliced by band without cross-checking.

### 1.4 How "blocking" was read

`blocking_status` is free prose written per row, so a keyword search over-counts: 22 rows say
"blocks nothing" or "blocks neither" and contain the word *block*. The plan therefore reports four
literal, separately counted facts, and treats every one of them as a **lower bound**:

| Reading | n |
|---|---|
| `blocking_status` literally begins with "blocks" | 78 |
| …of those, names the public release | 8 |
| …of those, names submission | 3 |
| …of those, names neither regime (blocks a *claim*, a *statement*, *reuse*) | 69 |
| `blocking_status` begins with "neither" | 72 |

Only two rows name **both** regimes: `CQA-A-01` (corpus never reached curation closure) and
`CQA-C-01` (type vocabulary diverges from the declared CDM vocabulary). The four rows that begin
"publication (…)" — `CQA-P-01`…`P-04` — block traceability of a stated claim, not a release.
Regime counts are **never** totals; a row that "blocks nothing" can still make a defensible sentence
false, which is the failure mode most of the `DOC` band is designed to prevent.

### 3.1 Rank 1 — the only true external gate

`CQA-N-01` is first because it is the only critical finding whose resolution is outside the project's
control. The 179 papers are **not homogeneous**: 135 are a licence-determination problem (quotable
under exceptions, jurisdiction-dependent), 29 a derivative-work problem, 15 an NC-compatibility
problem. Routing them as one queue will produce the wrong answer for at least two of the three.
The commissionable work exists — `submission_readiness/LEGAL_LIBRARY_REVIEW_PACKAGE.csv` is ready and
unsent (B1) — and until it returns, the correct manuscript word is **PENDING**, not "restricted".
This audit does not simulate that review, and no LLM may.

### 3.2 Ranks 2–3 — the redaction asymmetry (one defect, two faces)

`CQA-F-01` and `CQA-N-02` are the same divergence seen from the catalogue side and the database side.
The catalogue redacts **18,502** licence-restricted cells (and 3,529 `gap_evidence` rows); the CDM
carries the same text unredacted and has **no column that can mark a redacted cell**. Neither
database can express "this value was withheld". The cheapest honest resolution is a statement, not a
rebuild: add `evidence_redacted` to the data dictionary and declare the DB deliberately unredacted
and mask-on-export. The expensive resolution is a rebuild that masks at load. **The two must not be
left as an undiscovered difference**, because a reuser who joins CSV to DB will silently obtain text
the catalogue said was withheld. Note this is a *licensing* asymmetry, not a leak: the frozen public
build `releases/zenodo_frozen/` was rescanned and has 0 leaks (component N, B3).

### 3.3 Ranks 4–5 — the schema, stated rather than rebuilt

`CQA-H-01` and `CQA-M-01` are the same measurement reported by two components: **866 / 866** columns
are declared type `NONE`, **0** foreign keys exist, `journal_mode = delete`, no view, no declared
relationship anywhere. A consumer cannot generate a target DDL from this file; they must infer 866
types from data — which is what this audit had to do. The action is **not** to rebuild the DB (which
is frozen and checksummed). It is to **ship the DDL that was always intended**: column affinities,
primary keys, `FOREIGN KEY` declarations even with enforcement off, and a junction table for the five
parent lists a consumer would otherwise have to reverse-engineer. That converts an undocumented
implicit schema into a documented one without changing a single row.

### 3.4 Ranks 6–12 — seven disclosures

These seven are `DOC` precisely because the underlying facts are measured and final; what is missing
is a sentence. Each is a case where the *number* is defensible but the *implied reading* is not:

- **`CQA-C-01`** — the release uses 15 type values against a declared vocabulary of 14. Publishing the
  observed typology with the 8 extensions explicitly labelled as extensions is honest; remapping now
  would change frozen records. This row names **both** publication and release — it is one of only two
  critical rows that do.
- **`CQA-D-01`** — 35,063 of the mapping rows are reuse from an earlier CPU pass and 36,475 are
  net-new; nothing was re-queried, and the frozen table cannot be regenerated. Describe the reuse-first
  design as a design; do not describe it as a fresh lookup.
- **`CQA-E-01`** — 6,773 definitions is a real number over a 162,409-term vocabulary: **2.09%**. The
  figure must never appear without its denominator in the same sentence.
- **`CQA-G-01`** — `subject_ontology_id` / `object_ontology_id` are `unresolved` on 25,788 / 25,788
  triples (stage 57 evidently never ran). Publish them as reserved-and-unpopulated, and do not claim
  ontology grounding anywhere in the manuscript.
- **`CQA-G-02`** — 68.7% of triples sit in one escape bucket. If the abstract quotes a triple total,
  the split is part of that number, not a footnote. The cleaned relabelling belongs in a **separate**
  artefact with its own error profile (component J), never merged into the frozen count.
- **`CQA-I-01`** — the tier discipline failure. A public-benchmark F1 exists for 5 entity types on
  PubMed text; it does not speak to this corpus, which has no gold standard. The risk is not the
  number, it is the adjacency: benchmark and corpus results in one section invite the reader to carry
  the F1 across. This row is the one critical finding that touches publication but **not** release,
  and it is the finding this audit would rank highest on scientific-integrity grounds alone.
- **`CQA-M-04`** — 90.7% of concepts are unnamed and 0% of triples carry an ontology id, so the
  bundle loads but does not *link*. State the ceiling; point readers to `term_concept_map` as
  candidates, not as mappings.

### 4.1 The two human gates (13–14)

`CQA-K-02` and `CQA-K-03` are the cheapest credibility gain in the entire register. The BugSigDB
comparison already has an adjudication column with nine fields, and all nine are empty. Adjudicating
≈150 items (10%) produces a disagreement rate — a real number where there is currently a designed
silence. The 57 `body_site` mismatches are a one-afternoon read that decides whether the 24.6%
concordance is a defect in the comparison or in the matching rule. Both are small, both are decisive,
and neither can be produced by an algorithm without becoming a model verdict in disguise.

### 4.2 The two rebuild items (15–16)

`CQA-F-02` loses cell-level provenance for `assay`, `data_asset` and `claim` — the columns parse
cleanly (`csv_unparsable = 0` in every table), so this is a loader omission, not a data problem. Until
the next build, the correct statement is which three tables lost provenance and a pointer to the CSV
release for `assay`/`claim`. `CQA-I-09` is unrecoverable: entities off the schema were **deleted at
write time** (invalid types up to 69.0% of emitted strings), so type-agnostic scoring cannot be
reconstructed retrospectively. Its action is a disclosure plus a change for the next run.

### 4.3 The nineteen artefact additions (17–31)

Nineteen of the 43 HIGH rows add a file rather than change a value, and they cluster into five
repeated shapes — this is why the class matters more than the count:

- **A label vocabulary.** `CQA-D-03`, `CQA-D-04`, `CQA-F-03`, `CQA-G-12`: model-assigned labels are
  being read as verdicts. Ship the vocabulary, the off-vocabulary values, and the cross-tab, so a
  consumer can filter instead of guessing.
- **A three-tier number instead of a single rate.** `CQA-F-04`, `CQA-F-05`, `CQA-G-03`, `CQA-J-02`:
  locatability, literal correspondence and sentence-level traceability each hide three populations
  behind one percentage. Report the tiers with counts and the verb set for each; never a single
  locatability figure.
- **An exclusion flag instead of a deletion.** `CQA-G-04` (1,619 triples with zero verified
  evidence), `CQA-F-06` (the 1.5× filter), `CQA-F-07` (duplicate dataset groups). Publishing the flag
  preserves the frozen population; dropping the rows would silently change it.
- **A deployability column.** `CQA-I-03`: the top-ranked BC5CDR result is an in-domain database
  lookup that cannot be used for section NER. Ranking without a `deployable_on_sections` column is
  actively misleading.
- **A schema/documentation artefact.** `CQA-H-02` (split rule per column), `CQA-M-02` (column-level
  CSV↔DB crosswalk), `CQA-J-01` (the rubric), `CQA-J-03` (mention-count distribution).

`CQA-J-01` carries the `human_required` flag for a specific reason: 60.7% is a **model verdict**, and
the rubric that produced it is not shipped. Publish the rubric and spot-check 50 drops before the
number is quoted as fact. `CQA-H-08` is a one-line query rewrite (Q7 asks for a storage condition and
returns its opposite because the minus sign is destroyed upstream, `CQA-F-11`); re-express the case
rather than repair the data.

### 4.4 The twenty-four disclosures (32–55)

Twenty-four HIGH rows are text, and they share one failure mode: **a true number carrying an untrue
implication.** The pattern repeats across components, so the plan treats them as one workstream
rather than 24 tasks:

| Pattern | Rows |
|---|---|
| A rate quoted without its denominator or population | `CQA-K-01` (47/453), `CQA-L-01` (50.4% vs 13.18%), `CQA-L-03` (46.5% name-only), `CQA-C-02` (72,610/162,409), `CQA-D-05` (11,477 no-candidate vs 85,663 never-queried — different claims) |
| A blended distribution presented as if homogeneous | `CQA-B-03` (`en_core_sci_lg` generic label on 38%), `CQA-C-02` (`ENTITY` 55.29%), `CQA-C-03` (provenance 3.06%) |
| Two columns that disagree, with no guidance | `CQA-F-03` (802 rows; the anchor is recomputable, the flag is inherited), `CQA-H-04` (40.6% stale), `CQA-H-06` (45.6% redundant), `CQA-L-02` (two CTD readings) |
| A sentinel that reads as breakage | `CQA-H-03`, `CQA-P-03`, `CQA-D-08` — all three are the **same** 5,237-row `NOT_IN_TERMINOLOGY` set seen from three components. Fix it once, in three places, and do **not** delete the sentinel. |

`CQA-A-01` deserves its own note: the corpus never reached curation closure, so inclusion was a
retrieval criterion, not a screening decision. The honest fix is a sentence describing the criterion
— **not** a retroactive backfill, which would be new annotation produced after the fact. `CQA-N-03`
is a genuine either/or: change the constants to `W=50, STRIDE=1` and re-run (minutes on 1.06 M cells,
not hours), or correct the README to "59 characters or more" and list the 403 violating cells.
Doing neither is the only wrong option. `CQA-N-05`'s 927 / 338 canonical-term losses are
**unattributed** (those tables have no `paper_id`) and need their own explanation, not inclusion in
the "withheld papers" bucket.

## 8. What this plan does not do

- **It does not execute anything.** No file outside this audit directory is modified; no frozen
  release is touched; no metric is re-derived. Every action is written in the imperative for a
  future operator.
- **It does not convert disclosure into a fix.** A `DOC` row resolves the *claim*, not the *defect*.
  The type vocabulary still diverges after `CQA-C-01` is written up; `CQA-C-01`'s own status remains
  open in `15_ISSUE_REGISTER.csv`. The plan says this explicitly so no reader mistakes a closed
  amendment for a closed issue.
- **It does not certify any number.** Where an action recommends reporting a figure, the figure is the
  one the corresponding component measured — not one this plan verified. Report 17's claim register
  analysis governs how those numbers may be stated.
- **It does not touch the §12 calibration or the terminology release.** Those are component B/E
  findings already reconciled by amendment (`CQA-B-AMEND-2026-11-05-1`) and are not re-opened here.
- **It does not re-order the bands by preference.** The rank order is fixed and mechanical
  (§1.2). A row at rank 60 is not less important than rank 55; it is in a lower severity band, which
  is a different statement.
- **It does not schedule.** No dates are proposed. The six `HUM` items depend on people outside the
  project, and the thirteen `BLD` items depend on a decision to open a new build cycle — neither is
  this audit's call.
- **It does not recommend changes to the frozen releases.** Where the only correct action is "state
  it", the word *fix* is not used.
